## 已修复的边界

| 问题 | 修复 |
|---|---|
| 收到业务 Error 完成事件后，本轮循环可能仍继续调度 | 排空事件后立即检查终止标记，阻止额外业务派发 |
| 旧 Consumer 退休过程中触发重平衡回调，可能污染新归属记录 | 订阅回调捕获实例标识；退休实例和旧实例的回调直接失效 |
| 个别批次结束路径可能在仍有恢复期限时清零失败计数 | 健康恢复入口统一检查创建、poll、提交期限及在途请求 |
| 对 FAILED 容器再次 start 可能静默无效 | 单个/全部启动前校验终态，明确报错 |
| pause 与数据 poll 返回竞争时，可能错误准入新批次 | 暂停登记与批次准入共用控制锁；尚未准入的批次有界暂存 |
| 异步提交失败后盲目重试可能导致旧进度回退 | 每实例一个提交请求在途，回调关联请求与分区版本；由协调循环重试 |

## 核对的核心不变量

- 注册不创建 Consumer、不连接 Kafka、不启动线程。
- 一个 Listener 仅有一个消费协调线程；业务线程不访问 Consumer。
- 多方暂停按 owner 集合管理，重复操作幂等；全局与本地作用域独立。
- start 不移除暂停记录，也不绕过退避期限；resume 不启动从未 start 的 Listener。
- 普通暂停允许当前完整批次处理、异步提交；业务抛错按日志跳过继续。
- 不在提交回调中阻塞或递归重试，不使用 commitSync 兜底。
- 维护性 poll 与故障恢复计时独立；仅 pause 分区不会停止成员维护。
- 未确认提交不能冒认成功；未执行记录不能提前提交。
- 分区撤销/丢失和实例重建后，旧业务结果与旧提交回调失效。
- close 共享总等待预算；不强行中断业务，不再准入下一批。
- 没有提交 target、诊断数据、构建工具、代理配置或凭据。

## 实际边界

- 真实 broker 测试使用单节点、单分区，未验证多 broker 故障转移、长时间网络隔离、认证环境或所有旧版本兼容性。故障注入单元测试覆盖框架的相应恢复分支。
- 严格异步提交下，重平衡收尾不能保证最后进度已经落盘，允许重复消费；业务需要幂等。
- 普通业务异常采用日志跳过，框架不保证业务最终成功。
- 永久阻塞的业务不能由框架安全强杀；关闭等待有界，业务仍需自身超时控制。
- 这是首版实现，不包含跨进程暂停协调、动态订阅或跨批次流水线。
